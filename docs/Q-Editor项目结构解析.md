# Q-Editor 项目结构解析文档

## 项目概述

Q-Editor 是一个基于 Vue 3 + TypeScript 的问卷编辑器系统，采用低代码架构设计。系统支持问卷创建、组件市场浏览、可视化编辑等功能。

### 技术栈
- **框架**: Vue 3 (Composition API)
- **语言**: TypeScript
- **状态管理**: Pinia
- **路由**: Vue Router
- **UI组件库**: Element Plus
- **样式**: SCSS

---

| 文件 | 功能说明 |

| `common.scss` | 通用样式类，定义常用的CSS类名 |
| `coms.scss` | 组件相关样式 |

| `reset.scss` | 样式重置文件，消除浏览器默认样式差异 |
| `variables.scss` | 全局变量定义（颜色、字体、间距等） |

### 2. `/components/` - 组件目录

存放所有可复用的Vue组件。

#### 2.1 `/components/Common/` - 通用组件

| 组件 | 功能说明 |
|------|---------|
| `Header.vue` | 顶部导航栏组件，包含返回按钮、用户头像等 |

#### 2.2 `/components/SurveyComs/` - 问卷业务组件

问卷系统的核心组件目录，采用分层架构设计。

##### 2.2.1 `/components/SurveyComs/Common/` - 问卷通用组件

| 组件 | 功能说明 |
|------|---------|

##### 2.2.2 `/components/SurveyComs/EditItems/` - 编辑项组件

每个编辑组件对应业务组件的一个可编辑属性，实现属性的可视化编辑。

| 组件 | 功能说明 |
|------|---------|
| `TitleEditor.vue` | 标题编辑组件，编辑题目标题文本 |
| `DescEditor.vue` | 描述编辑组件，编辑题目描述文本 |
| `OptionsEditor.vue` | 选项编辑组件，编辑选择题的选项列表 |

##### 2.2.3 `/components/SurveyComs/Materials/` - 业务组件（题型组件）

**组件特点**:
- 接收 `serialNum`（题号）和 `status`（状态对象）作为props

### 3. `/configs/` - 配置目录

存放项目的配置文件。

#### `/configs/defaultStatus/` - 默认状态配置

定义每个业务组件的初始状态和对应的编辑组件映射关系。

| 文件 | 功能说明 |
|------|---------|
| `SingleSelect.ts` | 单选题的默认状态配置，定义了单选题的所有可编辑属性及其初始值 |
| `defaultStatusMap.ts` | 默认状态映射表，将组件名称映射到对应的配置函数 |

**配置结构** (以单选题为例):
```typescript
{
  type: 业务组件,
  name: 组件名称,
  id: 唯一标识,
  status: {
    title: { 标题状态, editCom: 标题编辑器 },
    desc: { 描述状态, editCom: 描述编辑器 },
    options: { 选项状态, editCom: 选项编辑器 },
    // ... 其他可编辑属性
  }
}
```

**设计理念**: 采用 JSON-Schema 思想，将业务组件的每个可编辑状态映射到对应的编辑组件，实现低代码的可配置性。

### 4. `/router/` - 路由配置目录

| 文件 | 功能说明 |
|------|---------|
| `index.ts` | 路由配置文件，定义应用的所有路由 |

**路由结构**:
- `/` - 首页（问卷列表）
- `/materials` - 组件市场
  - `/select-group` - 选择题组
    - `/single-select` - 单选题

    - `/option-select` - 下拉选择
    - `/single-pic-select` - 图片单选题
    - `/multi-pic-select` - 图片多选题
  - `/input-group` - 输入题组
  - `/advanced-group` - 高级题组
  - `/note-group` - 说明题组
  - `/personal-info-group` - 个人信息题组
  - `/contact-group` - 联系方式题组
- `/editor` - 问卷编辑器

**路由设计**: 采用嵌套路由，组件市场使用三级路由结构（组 -> 类型 -> 具体组件）。

### 5. `/stores/` - 状态管理目录

使用 Pinia 进行全局状态管理。

| 文件 | 功能说明 |
|------|---------|
| `useMaterial.ts` | 组件状态仓库，管理组件市场中的所有组件状态 |

**状态结构**:
```typescript
{
  currentMaterialCom: 当前选中的组件名称,
  coms: {
    [组件名称]: {
      type: 业务组件,
      status: { 所有可编辑属性的状态 }
    }
  }
}
```

**核心功能**:
- 维护当前选中的组件
- 存储所有业务组件的状态
- 支持动态添加新组件

### 6. `/types/` - 类型定义目录

TypeScript 类型定义文件，确保类型安全。

| 文件 | 功能说明 |
|------|---------|
| `index.ts` | 类型导出入口文件 |
| `common.ts` | 通用类型定义（Vue组件类型） |
| `editProps.ts` | 编辑属性类型定义 |

**核心类型**:
- `BaseProps`: 所有组件的基础属性（id, isShown, name, editCom）
- `TextProps`: 文本属性（用于标题、描述等）
- `OptionsProps`: 选项属性（用于对齐、字号等枚举值）
- `BaseStatus`: 所有组件共有的基础状态（标题、描述、位置、大小、粗细、斜体、颜色）
- `OptionsStatus`: 带选项的组件状态（继承 BaseStatus，增加 options 属性）

**类型设计**: 采用继承和组合的方式，实现类型的复用和扩展。

---

### 7. `/utils/` - 工具函数目录

| 文件 | 功能说明 |
|------|---------|
| `index.ts` | 工具函数集合 |

**核心函数**:
- `getTextStatus(props)`: 从 TextProps 中获取文本状态
- `getStringStatus(props)`: 从 OptionsProps 中获取选项数组
- `getCurrentStatus(props)`: 从 OptionsProps 中获取当前选中的索引
- `getStringStatusByCurrentStatus(props)`: 根据当前索引获取对应的选项值

**设计目的**: 封装状态读取逻辑，简化组件中的状态访问代码。

## 核心架构设计

### 1. 低代码架构

系统采用低代码设计理念，核心思想是：

**业务组件 + 编辑组件 + 状态配置 = 可配置的问卷系统**

- **业务组件**: 用户最终看到的题目类型（单选题、多选题等）
- **编辑组件**: 用于编辑业务组件属性的工具（标题编辑器、选项编辑器等）
- **状态配置**: 定义业务组件有哪些可编辑属性，以及每个属性对应哪个编辑组件

### 2. 状态驱动设计

每个业务组件的状态对象包含所有可编辑属性：

```typescript
status: {
  title: { status: '标题文本', editCom: TitleEditor },
  desc: { status: '描述文本', editCom: DescEditor },
  options: { status: ['选项1', '选项2'], editCom: OptionsEditor },
  // ... 其他属性
}
```

编辑组件通过修改状态对象来更新业务组件的显示。

### 3. 组件市场设计模式

组件市场采用**三栏布局**：
1. **组件选择**: 展示所有可用的业务组件
2. **实时预览**: 展示当前选中组件的最终效果
3. **属性编辑**: 根据组件配置动态加载对应的编辑组件

这种设计让用户可以：
- 浏览所有可用的题型
- 实时预览题目的外观
- 调整题目的各种属性

### 4. 类型安全

通过 TypeScript 的类型系统确保：
- 组件 props 的类型正确性
- 状态对象的结构一致性
- 编辑组件与业务组件的匹配关系

## 数据流向

### 组件市场数据流

```
用户点击左侧组件
    ↓
更新 store.currentMaterialCom
    ↓
中间预览区重新渲染（根据新组件的 status）
    ↓
右侧编辑面板重新加载（根据新组件的 status.editCom）
    ↓
用户在编辑面板修改属性
    ↓
更新 store.coms[组件名].status
    ↓
中间预览区自动更新（响应式更新）
```

### 编辑器数据流（规划中）

```
用户从组件市场选择组件
    ↓
拖拽到编辑器画布
    ↓
创建组件实例（复制默认状态）
    ↓
用户编辑组件属性
    ↓
更新组件实例状态
    ↓
实时预览更新
```

## 扩展性设计

### 1. 添加新题型

要添加新的题型组件，需要：

1. **创建业务组件**: 在 `/components/SurveyComs/Materials/` 下创建新组件
2. **创建编辑组件**: 如果需要新的编辑器，在 `/components/SurveyComs/EditItems/` 下创建
3. **配置默认状态**: 在 `/configs/defaultStatus/` 下创建配置文件
4. **注册到映射表**: 在 `defaultStatusMap.ts` 中注册新组件
5. **添加路由**: 在 `router/index.ts` 中添加路由
6. **创建视图**: 在 `/views/MaterialsView/` 下创建对应的视图组件

### 2. 添加新编辑器

要添加新的属性编辑器：

1. **创建编辑组件**: 在 `/components/SurveyComs/EditItems/` 下创建组件
2. **更新类型定义**: 在 `/types/editProps.ts` 中添加相关类型
3. **在配置中使用**: 在默认状态配置中引用新的编辑组件

## 项目特色

1. **低代码架构**: 通过配置而非编码来定义问卷组件
2. **组件化设计**: 高度模块化，易于维护和扩展
3. **类型安全**: TypeScript 提供完整的类型保护
4. **实时预览**: 组件市场支持实时预览和编辑
5. **灵活配置**: 每个组件的属性都可以独立配置和编辑
6. **响应式设计**: 基于 Vue 3 的响应式系统，状态变化自动更新视图

## 总结

Q-Editor 是一个设计精良的低代码问卷编辑器系统，采用 Vue 3 + TypeScript 技术栈，具有以下特点：

- **清晰的分层架构**: 组件、配置、状态、路由各司其职
- **高度可扩展**: 通过配置即可添加新题型和新编辑器
- **类型安全**: TypeScript 提供完整的类型保护
- **用户体验优秀**: 实时预览、可视化编辑

项目目前处于开发阶段，核心架构已经搭建完成，组件市场的基础功能已实现，编辑器功能待进一步开发。
