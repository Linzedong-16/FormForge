## 一、安全缺陷（严重 — 需立即修复）

### 1.1 [x] 验证码生成使用非加密随机数

| 项目               | 内容                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/user/auth.service.ts` `generateVerificationCode()`                                       |
| **问题描述** | `Math.random()` 生成的验证码可被预测，攻击者通过已知 JavaScript PRNG 状态可预测后续验证码，绕过邮箱验证注册/密码重置 |
| **影响范围** | 所有依赖邮箱验证码的业务（注册、密码重置）                                                                             |
| **改进建议** | 改用 `crypto.randomInt(100000, 999999).toString()`                                                                   |
| **已修复**   | 是                                                                                                                     |

### 1.2 [x] 管理员生成密码使用非加密随机数

| 项目               | 内容                                                                            |
| ------------------ | ------------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/user/admin.service.ts` `generateRandomPassword()` |
| **问题描述** | `Math.random()` 生成管理员创建用户时的默认密码，存在可预测风险                |
| **影响范围** | 管理员创建用户功能                                                              |
| **改进建议** | 改用 `crypto.randomBytes()` 生成安全随机密码                                  |
| **已修复**   | 是                                                                              |

### 1.3 [x] SMTP 密码明文存储

| 项目               | 内容                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/user/admin.service.ts` `updateSystemConfig()`                                    |
| **问题描述** | SMTP 密码以明文 `smtp_password` 存入 `systemConfig` 表，数据库泄露将直接暴露 SMTP 凭据，被用于发送钓鱼邮件 |
| **影响范围** | 系统配置管理、邮件发送                                                                                         |
| **改进建议** | AES-256-GCM 对称加密存储，密钥由环境变量注入；读取时自动解密                                                   |
| **已修复**   | 是（新增 `utils/crypto.ts`，`CRYPTO_ENCRYPTION_KEY` 环境变量）                                             |

### 1.4 [x] 前端上传手动设置 Content-Type 导致 boundary 丢失

| 项目               | 内容                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **位置**     | `app/q-editor/src/api/upload.ts`                                                                                                               |
| **问题描述** | 手动设置 `headers: { "Content-Type": "multipart/form-data" }` 会覆盖浏览器/axios 自动生成的 `boundary` 参数，后端无法正确解析 multipart 数据 |
| **影响范围** | 图片上传功能                                                                                                                                     |
| **改进建议** | 删除手动 `Content-Type` header，让 axios 自动处理                                                                                              |
| **已修复**   | 是                                                                                                                                               |

### 1.5 [x] 上传超时时间不一致

| 项目               | 内容                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------ |
| **位置**     | `app/q-editor/src/api/upload.ts` vs `server.ts`                                                          |
| **问题描述** | 上传超时设为 30s，但 `serverClient` 轴向超时仅 15s，15s 一到 axios 触发 `ECONNABORTED`，30s 超时永不生效 |
| **影响范围** | 大文件上传                                                                                                   |
| **改进建议** | 上传请求在调用时覆盖 `timeout` 配置                                                                        |
| **已修复**   | 否（经分析，axios 单次请求 `timeout` 会覆盖实例默认值，实际 30s 生效）                                     |

## 二、安全缺陷（高危 — 建议尽快修复）

### 2.1 [x] sendCode 中 RabbitMQ 发送邮件同步阻塞响应

| 项目               | 内容                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/user/auth.service.ts` `sendCode()`                        |
| **问题描述** | `await sendToQueue(...)` 同步等待消息入队，RabbitMQ 慢/不可用时拖慢验证码发送接口响应 |
| **影响范围** | 验证码发送接口响应时间                                                                  |
| **改进建议** | 改为 `sendToQueue(...)` 不 await，让邮件发送异步化，异常仅记录日志                    |
| **已修复**   | 是（`sendToQueue` 返回 `boolean` 非 Promise，改为 `try-catch` 包裹）              |

### 2.2 [x] verifyToken 缓存访问存在竞态窗口

| 项目               | 内容                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/user/auth.service.ts` `verifyToken()`                                                         |
| **问题描述** | 使用 `cache.get` + `cache.set` 两步操作，而非 `cache.getOrSet`。同一用户并发请求时，缓存 miss 会导致多个请求同时查 DB |
| **影响范围** | 所有需要 Token 校验的接口                                                                                                   |
| **改进建议** | 改为 `cache.getOrSet` 统一 Cache-Aside 访问模式                                                                           |
| **已修复**   | 是                                                                                                                          |

### 2.3 [x] 上传路由缺少请求体大小限制

| 项目               | 内容                                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/survey/upload.routes.ts`                                                                          |
| **问题描述** | 文件大小校验在 `toBuffer()` 之后，但 Fastify 层面没有配置 `bodyLimit`。攻击者发送超大文件会在 `toBuffer()` 阶段占满内存 |
| **影响范围** | 文件上传接口、服务器内存安全                                                                                                  |
| **改进建议** | 在 Fastify 路由上配置 `bodyLimit: 10 * 1024 * 1024`（10MB），在读取 buffer 之前就拒绝超大文件                               |
| **已修复**   | 是                                                                                                                            |

### 2.4 [ ] 问卷列表缓存 key 含冗余字段

| 项目               | 内容                                                                      |
| ------------------ | ------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/survey/survey.service.ts` `list()`          |
| **问题描述** | 缓存 key 中 `keyword` 为空时固定空字符串，虽不影响功能但增加了 key 冗余 |
| **影响范围** | 缓存 key 设计                                                             |
| **改进建议** | 确认缓存 key 设计是否合理，`keyword` 为空时应省略该维度                 |
| **已修复**   | 否（非功能性缺陷，暂缓）                                                  |

## 三、安全缺陷（中危 — 择机修复）

### 3.1 [x] publish/close 操作存在 TOCTOU 竞态

| 项目               | 内容                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| **位置**     | `app/q-server/src/modules/survey/survey.service.ts` `publish()` / `close()`                              |
| **问题描述** | `publish` 和 `close` 方法在事务外执行 `findFirst` 做状态校验，与事务内的 `update` 之间存在 TOCTOU 窗口 |
| **影响范围** | 问卷发布/关闭操作                                                                                              |
| **改进建议** | 将 `findFirst` 校验移入 `$transaction`，或 `update` 的 `where` 增加 `status` 条件                    |
| **已修复**   | 是（已将校验逻辑移入 `$transaction`）                                                                        |

### 12.1 AI 一键生成问卷

| 项目               | 内容                                                             |
| ------------------ | ---------------------------------------------------------------- |

| **复杂度**   | 中等                                                             |
| **状态**     | [ ] 待开发                                                       |

| **后端位置** | `src/modules/ai/chains/generate-survey.chain.ts`（待创建）     |

**业务描述：**

用户输入自然语言需求（如"生成一份大学生就业意向调查"），后端调用 LLM 生成结构化问卷组件，前端直接填充到编辑器中。

**技术方案：**

```
用户输入需求描述
       │
       ▼
POST /api/ai/generate
       │
       ▼
generate-survey.chain.ts
  ├─ ChatPromptTemplate（System: "你是问卷设计专家…"）
  ├─ ChatAnthropic / ChatOpenAI
  └─ .withStructuredOutput(SurveyComponentArraySchema)
       │
       ▼
SurveyComponentPayload[] → 前端 coms[] 直接渲染
```

**关键依赖：**

| 依赖                     | 用途                               |
| ------------------------ | ---------------------------------- |
| `@langchain/core`      | Chain 编排（已安装）               |
| `@langchain/anthropic` | Claude Sonnet 4（已安装）          |
| `zod`                  | 问卷组件 Schema 类型安全（已安装） |
| `config/langchain.ts`  | LLM 模型工厂（已有）               |

**子任务：**

| 编号   | 任务                                                                        | 状态 |

### 12.3 AI Agent — 数据洞察 + 自动整理数据

| 项目               | 内容                                                 |
| ------------------ | ---------------------------------------------------- |
| **优先级**   | 低（核心亮点，但依赖前两项完成）                     |
| **复杂度**   | 高                                                   |
| **状态**     | [ ] 待开发                                           |
| **后端位置** | `src/modules/ai/agents/insight-agent.ts`（待创建） |

**业务描述：**

用户用自然语言向系统提问数据问题，Agent 自动规划执行步骤、调用 Tool 查询数据库、汇总结果以可读文本返回。例如：

- "最近 7 天的问卷完成率是多少？"
- "哪个省份的人填的最多？男女比例如何？"
- "把第 3 题的选项分布整理成一目了然的数据"

**技术方案（LangGraph ReAct Agent）：**

```
用户自然语言提问
       │
       ▼
POST /api/ai/insight  { surveyId, question }
       │
       ▼
insight-agent.ts（ReAct Agent）
  ┌─────────────────────────────────────────┐
  │  LLM 思考："我需要查完成率"              │
  │      │                                  │
  │      ▼                                  │
  │  Tool: get_survey_stats(surveyId)        │
  │      │                                  │
  │      ▼                                  │
  │  返回 { total_responses: 234, ... }      │
  │      │                                  │
  │      ▼                                  │
  │  LLM 思考："还需要看按天的趋势"           │
  │      │                                  │
  │      ▼                                  │
  │  Tool: get_daily_responses(surveyId, 7) │
  │      │                                  │
  │      ▼                                  │
  │  返回 [{ date, count }, ...]             │
  │      │                                  │
  │      ▼                                  │
  │  LLM 汇总："最近 7 天共收到 234 份答卷，  │
  │           完成率 68%，呈上升趋势…"        │
  └─────────────────────────────────────────┘
```

**Tool Set 设计：**

| Tool 名称                     | 功能                             | 数据源                        |
| ----------------------------- | -------------------------------- | ----------------------------- |
| `get_survey_stats`          | 答卷总数、完成率、平均用时       | Prisma `response` 表        |
| `get_daily_responses`       | 按天统计答卷提交量               | `GROUP BY date(created_at)` |
| `get_province_distribution` | 答卷省份分布 TOP 10              | `GROUP BY province`         |
| `get_option_frequencies`    | 指定题目的选项频次分布           | `answers` JSON 解析         |
| `get_text_responses`        | 指定题目的文本回答摘要           | `answers` JSON 中 text 类   |
| `get_completion_trend`      | 完成率日趋势                     | 时序聚合查询                  |
| `get_cross_analysis`        | 两题交叉分析（如"性别 × 学历"） | JOIN / JSON 解析              |

**关键依赖：**

| 依赖                      | 用途                         |
| ------------------------- | ---------------------------- |
| `langgraph`             | Agent 状态图编排             |
| `@langchain/core/tools` | Tool 定义（`tool()` 工厂） |
| `createReactAgent`      | ReAct 模式 Agent             |

**子任务：**

| 编号   | 任务                                                       | 状态 |
| ------ | ---------------------------------------------------------- | ---- |
| 12.3.1 | 安装 `langgraph` 依赖                                    | [ ]  |
| 12.3.2 | 实现 7 个数据查询 Tool（`src/modules/ai/tools/`）        | [ ]  |
| 12.3.3 | 编写 Agent System Prompt（含 Tool 使用规则、禁止编造数据） | [ ]  |
| 12.3.4 | 实现 `insight-agent.ts`（ReAct Agent 创建 + 状态管理）   | [ ]  |
| 12.3.5 | 创建 `POST /api/ai/insight` 路由                         | [ ]  |
| 12.3.6 | 添加会话记忆（`RunnableWithMessageHistory`），支持追问   | [ ]  |
| 12.3.7 | 前端实现 AI 对话面板（类似 ChatGPT 聊天 UI）               | [ ]  |
| 12.3.8 | 支持流式输出（SSE），提升交互体验                          | [ ]  |

**安全注意事项：**

| 场景                       | 处理                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| 用户询问其他用户的问卷数据 | Agent 强制注入当前 `userId`，Tool 内部 `where` 条件校验            |
| LLM 幻觉编造数据           | System Prompt 强调"必须调用 Tool，禁止编造"，监控 `agent_scratchpad` |
| SQL 注入（`$queryRaw`）  | 所有 Tool 使用 Prisma 参数化查询，`surveyId` 用 `BigInt` 类型约束  |
| Token 消耗过大             | 限制最大迭代次数（`maxIterations: 5`），超过则返回部分结果           |
