# 快速验证指南：修复物料管理模块上传追踪缺失

**Created**: 2026-07-19 | **Phase**: 1

## 前置条件

- 数据库：PostgreSQL 已运行，`20260719120000_rename_survey_file_to_media_asset` 迁移已执行
- MinIO：对象存储服务已运行
- 后端：`pnpm --filter q-server dev`（监听 `:3000`）
- 前端管理端：`pnpm --filter frontend dev`（监听 `:5173`）
- 编辑器子应用：`pnpm --filter q-editor dev`（监听 `:5174`）
- 测试账号：至少一个普通用户 + 一个 super_admin 用户

## 场景 1: survey-engine PicItem 上传追踪 (US1, FR-001)

**目标**: 验证渲染引擎端图片选择组件上传后，物料管理页面可见。

### 步骤

1. 以管理员身份创建一个问卷，添加 PicItem（图片选择题）组件，发布问卷
2. 在浏览器新标签页或隐身窗口以普通用户身份打开填答页面
3. 点击 PicItem 的上传按钮，选择一张图片上传
4. 登录管理端 → 物料管理页面（`/media-assets`）
5. 在筛选栏"文件类型"下拉中选择 `survey_option_image`
6. 确认列表中包含步骤 3 上传的图片记录

### 预期结果

- 图片上传成功，填答页面正常展示预览
- 物料管理页面列表中包含该记录，`file_type` 为 `survey_option_image`
- `survey_id` 为对应问卷 ID

---

## 场景 2: q-editor PicItem 草稿阶段上传 (US3, FR-002/FR-003)

**目标**: 验证编辑器新建问卷（未保存）时上传图片仍被追踪。

### 步骤

1. 登录编辑器 → 新建问卷（不保存，不关闭页面）
2. 添加 PicItem 组件，上传一张封面图
3. 在管理端物料管理页面搜索该图片（按文件名）
4. 回到编辑器，保存问卷（Ctrl+S 或点击保存按钮）
5. 再次在物料管理页面查看该图片的 `survey_id`

### 预期结果

- 步骤 3：图片在物料管理页面可见，`survey_id` 显示为 "—" 或空
- 步骤 5：同一图片的 `survey_id` 更新为保存后获得的问卷 ID

---

## 场景 3: 头像上传物料登记 (US2, FR-005/FR-006)

**目标**: 验证头像上传后在物料管理中可见。

### 步骤

1. 以普通用户登录 → 个人设置页 → 上传新头像
2. 登录管理端 → 物料管理页面
3. 筛选：`file_type=user_avatar`、按上传时间倒序
4. 确认第一条记录为步骤 1 上传的头像，`survey_id` 为空

### 预期结果

- 物料管理页面中可见头像记录
- `file_type` 为 `user_avatar`，`survey_id` 为 null

---

## 场景 4: 头像强制删除 + 前端兜底 (US2/US5, FR-011/FR-012)

**目标**: 验证管理员删除正在使用的不合规头像后，用户端头像展示切换为用户名兜底。

### 步骤

1. 确认场景 3 中上传的头像记录 ID
2. 在物料管理页面找到该头像记录 → 点击删除 → 确认
3. 切换到普通用户窗口，刷新页面
4. 检查以下位置的用户头像展示：
   - 导航栏右上角用户头像
   - 个人设置页头像
   - （如有）评论区的用户头像
5. 再次查看管理端的物料管理页面，确认该记录已消失

### 预期结果

- 步骤 2：删除成功，提示"头像物料已删除"或确认消息
- 步骤 3-4：所有头像展示位置显示圆形彩色背景 + 用户名首字符的兜底头像（而非损坏图片图标或空白）
- 步骤 5：该头像记录已不在列表中

## 场景 5: file_type 筛选 (US4, FR-007/FR-008)

**目标**: 验证物料管理页面能按文件类型筛选。

### 步骤

1. 登录管理端 → 物料管理页面
2. 默认列表（无筛选）包含所有类型的物料
3. 在"文件类型"下拉中选择 `user_avatar` → 确认列表仅显示头像类型
4. 选择 `survey_signature` → 确认列表仅显示签名类型
5. 清除选择（点击清除按钮 X） → 确认恢复全部类型视图
6. 组合筛选：选择 `survey_option_image` + `review_status=pending`

### 预期结果

- 单选生效后列表 item 的 `file_type` 字段全部匹配所选值
- 清除后恢复无筛选状态
- 组合筛选返回交集结果

## 场景 6: 头像更换后旧记录保留 (US2, FR-005)

**目标**: 验证用户换头像后旧物料不丢失。

### 步骤

1. 普通用户上传头像 A → 物料管理页面可见记录 R_A
2. 普通用户上传头像 B → 物料管理页面可见记录 R_B
3. 按 `user_id` 筛选（普通用户 ID），确认两条记录都存在
4. 在普通用户窗口确认当前头像为 B

### 预期结果

- R_A 和 R_B 都存在于物料管理页面
- R_A 不是当前头像（管理员仍可手动删除）
- R_B 关联到当前 `UserProfile.avatar_url`
