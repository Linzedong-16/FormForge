# Feature Specification: q-editor GitHub Pages 静态演示

**Feature Branch**: `preview`

**Created**: 2026-07-24

**Status**: Draft

**Input**: User description: "帮我完成q-editor前端项目的搭建，要能部署在Github Pages静态服务做演示，为了保证演示大致功能顺利，要求填充假数据顺利闭环，目前虽然已经完成部分搭建，但总体上还是报错启动失败，页面白屏，需要对该实现重新规划，并排查本地预览报错问题"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 访问者一键登录体验演示系统 (Priority: P1)

作为潜在用户或评估者，我希望打开演示页面后能够无需注册即可一键登录，进入系统浏览问卷编辑器的核心功能，以便快速了解产品能力。

**Why this priority**: 这是演示的入口——如果无法登录，后续所有功能都无法展示。目前页面白屏问题阻塞了演示流程。

**Independent Test**: 在浏览器地址栏输入部署 URL，页面不白屏。点击"一键演示登录"按钮后成功跳转到工作台首页。

**Acceptance Scenarios**:

1. **Given** 用户首次访问 GitHub Pages 演示站点, **When** 页面加载完成, **Then** 显示登录表单，凭证已预填，且页面无 JavaScript 错误或白屏
2. **Given** 登录页已加载且凭证已预填, **When** 用户点击"一键演示登录"按钮, **Then** 系统在 2 秒内完成认证并跳转到工作台首页
3. **Given** 用户已登录演示系统, **When** 用户点击右上角头像, **Then** 显示用户面板，包含预设的头像（指向指定 GIF URL）、昵称、邮箱等信息
4. **Given** 用户刷新页面, **When** 浏览器重新加载, **Then** 页面正常渲染，不会出现白屏或路由 404

---

### User Story 2 - 浏览预置演示问卷 (Priority: P2)

作为潜在用户，我希望在登录后能看到多份预置的演示问卷，包括草稿和已发布状态，以便了解问卷管理功能。

**Why this priority**: 首页问卷列表是最核心的功能展示区域，必须能正常加载和渲染，才能让访问者了解产品核心价值。

**Independent Test**: 登录后首页展示 2-3 份演示问卷，包含标题、状态标签、题目数量等信息。

**Acceptance Scenarios**:

1. **Given** 用户已登录在首页, **When** 页面加载完成, **Then** 表格中展示至少 2 份预置问卷，含已发布和草稿状态
2. **Given** 首页显示问卷列表, **When** 用户点击某份问卷标题, **Then** 跳转到该问卷的预览页面，展示完整的问卷内容
3. **Given** 用户查看已发布问卷, **When** 问卷预览页加载完成, **Then** 所有题目组件（单选、多选、文本输入等）正常渲染

---

### User Story 3 - 体验问卷编辑器 (Priority: P3)

作为潜在用户，我希望能够进入编辑器，创建或编辑问卷，添加题目组件，体验拖拽排序等功能，以便评估编辑器的易用性。

**Why this priority**: 编辑器是产品的核心差异化功能，但其依赖的 API 调用较多，需要确保 Mock 数据覆盖完整。

**Independent Test**: 从首页点击"创建问卷"进入编辑器，能够添加组件到画布，组件正常渲染。

**Acceptance Scenarios**:

1. **Given** 用户在首页, **When** 点击"创建问卷"按钮, **Then** 进入编辑器页面，左侧显示题型选择面板
2. **Given** 编辑器已打开, **When** 用户选择一种题型（如单选题）, **Then** 组件出现在中间画布区域并可编辑
3. **Given** 画布中有多个组件, **When** 用户点击"预览"按钮, **Then** 跳转到预览页，所有组件按序呈现
4. **Given** 用户在编辑器中修改了组件配置, **When** 点击"保存", **Then** 系统提示保存成功（本地存储，不依赖后端）

---

### User Story 4 - 浏览组件市场和模板 (Priority: P4)

作为潜在用户，我希望浏览组件市场和模板市场，查看可用的题型和预设模板，了解平台的扩展能力。

**Why this priority**: 组件市场和模板市场展示平台的丰富性，但属于辅助展示功能。

**Independent Test**: 从导航进入组件市场，能看到各题型分组的预览；从编辑器进入模板市场，能看到预设模板列表。

**Acceptance Scenarios**:

1. **Given** 用户在首页, **When** 点击"组件市场"按钮, **Then** 进入组件市场，左侧显示题型分组，右侧展示对应的组件预览
2. **Given** 用户在编辑器中, **When** 切换到模板市场 tab, **Then** 显示至少 3 个预设模板，包含名称、分类、使用次数等信息

---

### User Story 5 - 个人设置与主题切换 (Priority: P5)

作为潜在用户，我希望体验个人设置页面（头像、昵称修改、密码修改等）和主题切换功能（亮色/暗色/色弱模式），了解平台的个性化能力。

**Why this priority**: 辅助功能，但能体现平台的完整性和用户体验细节。

**Independent Test**: 进入设置页面能看到预填的用户资料，切换主题后页面样式正确变化。

**Acceptance Scenarios**:

1. **Given** 用户已登录, **When** 进入个人设置页面, **Then** 表单预填头像（指定 GIF URL）、昵称、职业、兴趣标签等
2. **Given** 用户在任意页面, **When** 点击头像面板中的暗色模式开关, **Then** 页面切换为暗色主题且所有组件样式正确
3. **Given** 用户在任意页面, **When** 切换色弱模式（如红色盲）, **Then** 页面色彩方案切换为对应的色弱友好配色

---

### Edge Cases

- 当用户直接通过 URL 访问子路径页面（如 `/home`、`/editor/1`）并刷新时，SPA 路由是否正确处理不存在的物理路径？
- 当浏览器禁用了 localStorage 或 IndexedDB 时，系统是否能优雅降级而不完全白屏？
- 当 API Mock 数据未覆盖某个被调用的接口时，页面如何处理（显示错误提示 vs 直接崩溃）？
- 当用户连续快速点击登录按钮时，是否会触发多个并发请求导致状态异常？

## Requirements _(mandatory)_

### Functional Requirements

**部署与启动**

- **FR-001**: 系统必须能通过 `pnpm build:standalone` 构建为纯静态文件（HTML + JS + CSS），无需任何后端服务
- **FR-002**: 构建产物必须能部署到 GitHub Pages 并通过浏览器访问，所有资源路径正确
- **FR-003**: 本地预览命令（`pnpm preview:standalone`）必须能正常启动并展示完整功能

**认证与用户**

- **FR-004**: 系统必须提供演示管理员账号，凭据写死在代码中（邮箱: `admin@example.com`，密码: `Admin@123`）
- **FR-005**: 登录表单在演示模式下必须自动预填管理员凭据
- **FR-006**: 系统必须提供"一键演示登录"按钮，点击后跳过表单校验直接发起登录
- **FR-007**: Mock 认证接口必须返回固定的 Token 和用户信息（角色为 super_admin）
- **FR-008**: 用户面板（头像弹窗）必须展示硬编码的用户资料，头像使用 `https://linzex.top/upload/1759642363899.gif`

**问卷管理**

- **FR-009**: 首页必须预置至少 2 份演示问卷，其中至少 1 份已发布、1 份草稿
- **FR-010**: 每份演示问卷必须包含至少 3 个不同类型的题目组件（标题、单选、多选、文本输入等）
- **FR-011**: 问卷预览页必须正确渲染所有组件类型，样式与编辑时一致

**编辑器**

- **FR-012**: 编辑器必须能正常打开，组件选择面板正常展示
- **FR-013**: 用户添加组件到画布后，组件必须实时渲染且可交互编辑
- **FR-014**: 保存操作必须将数据存储到本地 IndexedDB，并提示保存成功

**Mock 数据覆盖**

- **FR-015**: 客户端 Mock 系统必须拦截所有 `/api/*` 请求并返回预设的假数据
- **FR-016**: Mock 系统必须覆盖认证、用户、问卷、模板、设置、管理后台等全部 API 模块
- **FR-017**: 未匹配的 API 请求必须输出清晰的控制台警告，不应导致页面崩溃

**主题与设置**

- **FR-018**: 亮色/暗色主题切换必须正常工作
- **FR-019**: 色弱模式切换必须正常工作（红色盲、绿色盲、蓝色盲、全色盲）
- **FR-020**: 语言切换（中文/英文/日文）必须正常工作

### Key Entities

- **演示用户**: 固定的管理员账号，包含邮箱、密码、角色、头像 URL、个人资料等信息
- **演示问卷**: 预置的问卷数据，包含标题、描述、状态（草稿/已发布）、组件列表、创建时间等
- **演示模板**: 预置的模板数据，包含名称、分类、使用次数、评分、组件配置等
- **Mock 请求映射**: API URL + Method → 假数据响应的映射关系

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 任何用户首次访问 GitHub Pages 演示站点时，页面在 5 秒内完成加载且无 JavaScript 错误
- **SC-002**: 用户从打开登录页到成功进入首页的总操作时间不超过 10 秒（含页面加载 + 一次点击）
- **SC-003**: 100% 的预置演示功能可正常使用（登录、问卷列表、预览、编辑器、组件市场、设置、主题切换）
- **SC-004**: 页面刷新后不出现白屏或 404 错误，所有路由正确重定向到 `index.html`
- **SC-005**: 所有 API 请求在浏览器 Network 面板中显示为 200 状态码或完全不发出（由客户端 Mock 拦截）
- **SC-006**: 本地执行 `pnpm preview:standalone` 后，能在 1 分钟内启动预览服务器并正常访问

## Assumptions

- 目标部署环境为 GitHub Pages，使用 `/<repo-name>/` 作为子路径
- 演示仅展示前端功能，不需要真实的后端服务或数据库
- 用户使用现代浏览器（Chrome 90+、Edge 90+、Firefox 90+、Safari 14+），不支持 IE
- 问卷数据的持久化使用浏览器的 IndexedDB，不会跨设备同步
- 演示站点不需要埋点监控上报（tracking SDK 在演示模式下静默失败不阻塞用户体验）
- Mock 数据的更新频率与前端代码更新一致，无需独立维护
- demo 用户资料（头像、昵称等）为硬编码值，不需要修改功能
