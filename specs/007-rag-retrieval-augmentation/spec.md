- Q: 明确 ai-service 不直连 Postgres 之后，持久化内容（问卷模板、知识文档）的 Embedding 计算、pgvector 存储与检索三个环节具体由谁负责，权责边界是否清晰？ → A: 三个环节全部由拥有该数据持久化权属的一方（q-server）独立完成，计算与存储/检索不跨服务拆分；ai-service 不为任何需要持久化的数据发起 Embedding 计算，仅通过既有内部 API 获取检索结果。语义聚类等一次性、不持久化场景仍按前一条澄清，允许 ai-service 自行临时计算。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - AI 生成问卷时参考历史优质模板 (Priority: P1)

用户在使用"AI 生成问卷"功能输入意图（如"我想做一个员工满意度调查"）时，系统应先从已发布的历史优质问卷模板中，找出与用户意图语义相关的模板，并将这些模板作为真实参考样例提供给生成过程，使生成的问卷题型更合理、更贴近真实业务场景，而不是仅依赖少量固定的示例。

**Why this priority**: 问卷生成是当前 AI 能力中使用频率最高、用户最直接感知质量差异的功能。现状是生成质量依赖硬编码的少量示例，题型"模板化"、"千篇一律"问题突出，是当前用户体验的最大痛点，改进后收益最直接。

**Independent Test**: 可独立测试——给定一个具体调查意图，对比"启用历史模板检索"与"不启用"两种情况下生成的问卷，验证启用检索后生成结果中出现更合理、更贴近该类调查常见题型的比例更高；且该能力可单独上线、单独回滚，不依赖后续两个用户故事。

**Acceptance Scenarios**:

1. **Given** 系统中已有若干发布过的高质量问卷模板，**When** 用户输入生成意图并触发 AI 生成，**Then** 系统必须先检索出与意图语义相关的历史模板，并将其作为参考信息注入生成过程，最终生成的问卷内容与检索到的模板在题型分布上具备合理的相关性。
2. **Given** 模板库中暂无任何数据（冷启动场景），**When** 用户触发 AI 生成，**Then** 系统必须正常降级为原有的生成方式完成生成，不能因检索无结果而报错或生成失败。
3. **Given** 用户在生成意图中包含专有名词（如"NPS"、"eNPS"），**When** 触发检索，**Then** 系统必须能够精确命中包含该关键词的历史模板，而不仅依赖语义相似度召回。
4. **Given** 登录用户希望查看与自己意图相关的历史模板，**When** 用户主动发起"相似模板"检索请求，**Then** 系统必须返回按相关度排序的模板列表及每个模板的关键信息（标题、相关度、所属题型数量等）。

### User Story 2 - 开放题答卷语义主题聚类分析 (Priority: P2)

问卷创建者/分析人员在查看某道开放题的答卷分析结果时，希望系统能把语义相近但用词不同的回答（例如"服务态度好""客服很耐心""响应速度快"）自动归入同一主题，并给出该主题的代表性描述、样本数量与整体情感倾向，而不是像现状一样仅按关键词共现粗略分组，导致同义表达被错误地拆分到不同类别。

**Why this priority**: 该能力直接提升问卷分析场景下"开放题洞察"的可用性和可信度，是分析人员做决策的重要依据，但其价值建立在已有的问卷与答卷数据基础上，优先级次于生成环节的即时体验提升。

**Independent Test**: 可独立测试——针对同一批已有的开放题答卷样本，分别用现状的关键词共现分组与新的语义主题聚类分组，人工比对二者对"同义不同字"回答的分组准确性，验证新方式的分组结果更贴近人工判断；该能力可作为分析流程中的独立环节单独启用。

**Acceptance Scenarios**:

1. **Given** 某道开放题已收集到足够数量的文本答卷，**When** 分析人员请求该题的语义主题聚类结果，**Then** 系统必须返回若干主题簇，每个簇包含主题标签（或代表性描述）、代表性原文、簇内样本数、以及该簇的整体情感倾向评分。
2. **Given** 一批语义相近但字面完全不同的回答，**When** 执行语义主题聚类，**Then** 这些回答必须被正确归入同一主题簇，而不是像关键词共现方式那样被拆分到不同类别。
3. **Given** 某道开放题的有效答卷数量低于可聚类的最小样本量，**When** 分析人员请求聚类结果，**Then** 系统必须明确提示"数据量不足，无法进行语义聚类"，不得返回无意义或误导性的分组结果。
4. **Given** 存在少量无法归入任何主题的异常/噪声回答，**When** 执行聚类，**Then** 系统必须能将其标记为噪声/未分类，而不是强行归入某个不相关的主题簇。

### User Story 3 - 问卷设计助手基于知识库的可追溯问答 (Priority: P3)

用户在设计问卷时向"设计助手"提出专业性问题（例如"量表题用 5 点还是 7 点？"），希望得到的回答是基于问卷设计方法论、统计规范等已沉淀的知识依据给出的，并能看到回答所引用的具体来源，而不是模型凭空生成、缺乏依据甚至可能误导用户的回答。

**Why this priority**: 该能力提升的是"专业咨询"场景的可信度，属于锦上添花型能力，覆盖用户面相对生成、分析场景更小，且依赖知识库内容的预先建设，因此优先级最低，但仍是完整 RAG 能力闭环的重要组成部分。

**Independent Test**: 可独立测试——预先准备一份问卷设计方法论知识文档并完成入库，向设计助手提出该文档覆盖范围内的问题，验证回答内容与知识库中的对应段落一致，且回答附带可核实的引用来源；对文档未覆盖的问题，验证系统会明确告知"未找到相关依据"而不是编造答案。

**Acceptance Scenarios**:

1. **Given** 知识库中已收录问卷设计方法论相关文档，**When** 用户向设计助手提出该文档覆盖范围内的问题，**Then** 系统必须先从知识库中检索相关内容片段，将其作为回答依据，并在回答中附上可追溯的引用来源（如文档标题、所属章节）。
2. **Given** 用户提出的问题在知识库中没有相关内容，**When** 设计助手生成回答，**Then** 系统必须明确告知用户"未找到相关依据"，不得伪装出虚假的引用来源。
3. **Given** 管理员上传了新的知识文档，**When** 文档完成入库处理，**Then** 后续相关问题必须能够检索到该文档的内容并在回答中体现。
4. **Given** 管理员需要下线或更新某份已过期的知识文档，**When** 执行删除/更新操作，**Then** 后续问答不得再引用该文档的旧内容。

### Edge Cases

- 检索服务（语义检索/关键词检索任一环节）出现故障或超时时，问卷生成、答卷分析、设计助手问答三大场景应如何降级，确保主流程不中断？
- 同一份问卷被多次编辑并重新发布时，如何避免历史版本的索引内容与最新内容同时存在造成检索结果重复或过时？
- 用户输入的检索查询内容异常（超长文本、空字符串、无意义乱码）时，系统如何处理？
- 不同用户/租户之间的问卷模板与答卷数据是否可能被检索接口跨越权限边界返回？
- 知识库文档内容更新后，旧版本引用是否会继续出现在新的问答结果中？
- 答卷开放题文本中包含可能识别到具体填写人身份的信息时，索引与检索环节如何处理，是否需要脱敏？
- 语义聚类结果中出现明显偏离主题的异常文本（如无意义灌水内容）时，是否会被错误地当作某一主题的"代表句"？

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须能够将已发布的问卷模板内容转换为可供语义检索的索引条目，且该索引在问卷发布或内容更新时自动保持同步，无需人工手动维护。
- **FR-002**: 系统必须提供管理员手动触发指定问卷重新建立索引、以及删除某问卷索引的能力，用于处理异常数据或问卷下线场景。
- **FR-003**: 当用户使用 AI 生成问卷功能并输入意图描述时，系统必须先从已索引的历史问卷模板中检索出与该意图语义相关的模板，并将其作为参考样例注入生成过程。
- **FR-004**: 检索能力必须同时结合"语义相似度召回"与"关键词精确匹配召回"两种方式进行综合排序（混合检索），以覆盖"表达不同但含义相近"和"专有名词精确命中"两类查询需求。
- **FR-005**: 系统必须支持调整语义检索与关键词检索在综合排序中的权重比例，以便针对不同业务场景优化检索效果。
- **FR-006**: 当模板库中暂无可用数据（冷启动）或某次检索未命中任何结果时，AI 生成问卷流程必须能够正常降级为不依赖参考模板的原有生成方式，不得报错或中断。
- **FR-007**: 系统必须为登录用户提供主动查询"相似历史问卷模板"的能力，返回结果需包含相关度排序及模板关键信息。
- **FR-008**: 系统必须提供对指定问卷指定开放题的所有答卷文本进行"语义主题聚类"的能力，将语义相近的自由文本自动归入同一主题，而不仅依赖关键词共现。
- **FR-009**: 每个语义主题聚类结果必须包含：主题标签（或代表性描述）、代表性原文、簇内样本数量、以及该簇的整体情感倾向评分。
- **FR-010**: 当某道开放题的有效答卷数量低于可支撑语义聚类的最小样本量时，系统必须明确返回"数据量不足，无法聚类"的提示，不得返回无意义或误导性的分组结果。
- **FR-011**: 语义聚类结果必须能够将无法归入任何主题的异常/噪声文本单独标记，不得强行归入某个不相关主题。
- **FR-012**: 系统必须支持将问卷设计方法论、统计规范等参考资料以知识文档形式导入知识库，并支持管理员对知识库内容进行新增、更新、删除维护。
- **FR-013**: 当用户向设计助手提出问题时，系统必须先从知识库中检索与该问题相关的内容片段，并将其作为生成回答的依据注入。
- **FR-014**: 设计助手基于知识库生成的回答，必须同时提供其所依据的引用来源信息（如文档标题、所属章节），供用户核实与追溯。
- **FR-015**: 当知识库中未检索到与用户问题相关的内容时，设计助手必须明确告知用户"未找到相关依据"，不得在缺乏依据的情况下伪造引用来源或凭空回答。
- **FR-016**: 涉及向量化索引与检索的数据（问卷模板文本、答卷开放题文本、知识文档）必须遵循现有的数据访问权限与隔离规则，用户只能检索到其有权访问范围内的数据，不得跨用户/跨权限边界返回未授权内容。
- **FR-017**: 系统必须在该能力上线前，明确记录被向量化存储内容涉及的数据留存周期与个人信息处理方式（是否包含可识别答卷填写者身份的信息、留存时长、清理/删除机制）。
- **FR-018**: 新增的索引管理类操作（重建索引、知识库维护）必须仅限管理员角色执行，检索/查询类操作面向已登录用户开放。
- **FR-019**: 系统必须对检索请求的输入长度与单次返回结果数量设置合理上限，防止异常输入导致性能劣化或资源滥用。
- **FR-020**: 当底层检索能力出现故障或响应超时时，问卷生成、答卷分析、设计助手问答三大场景必须能够跳过检索环节继续完成各自的核心流程，不得因检索环节异常导致整体功能不可用。
- **FR-021**: 涉及跨服务集成的检索/存储能力，必须遵循现有"ai-service 仅通过内部 API 鉴权的 HTTP 接口访问 q-server 能力"的既有集成边界，不得新增 ai-service 直接连接 q-server 数据存储的通道；对于无需长期复用的一次性 Embedding 计算（如语义聚类场景中的答卷文本），可在计算完成后不做持久化存储。
- **FR-022**: 涉及持久化存储的 Embedding 计算能力，必须与该数据的持久化存储、检索能力归属同一方（q-server），不得将"计算"与"存储/检索"拆分给不同服务承担；ai-service 不得为任何需要长期复用的持久化数据（问卷模板、知识文档）单独发起 Embedding 计算调用，该类数据的 Embedding 生成、写入与检索全部由 q-server 完成并通过既有内部 API 对外提供结果。

### Key Entities _(include if feature involves data)_

- **问卷模板索引片段**：由已发布问卷的标题描述、题目内容等切分而成的可检索文本单元，携带来源问卷标识、片段类型（标题描述/题目/整体）及题型分布、答卷数、评分等附加信息，用于生成场景与相似模板推荐场景的检索。
- **知识文档片段**：由问卷设计方法论、统计规范等知识文档切分而成的可检索文本单元，携带所属文档标识、文档标题、片段序号及章节等附加信息，用于设计助手问答场景的检索与引用。
- **检索请求与结果**：用户或内部流程发起的一次查询，包含查询文本、检索范围（如仅限某问卷/某类文档）、返回数量等参数，结果为按相关度排序的候选片段列表及各自的相关度评分。
- **语义主题聚类结果**：针对某道开放题的一次聚类分析产出，包含若干主题簇（各自的标签、代表原文、样本数量、情感倾向评分）及未能归类的噪声样本数量。
- **引用来源**：设计助手回答中标注的依据来源，关联至具体的知识文档片段，包含文档标题、章节等可供用户核实的定位信息。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 启用历史模板检索增强后，AI 生成问卷中题型明显不合理（与调查主题不匹配）的比例相较现状降低 30% 以上（以人工抽样评审衡量）。
- **SC-002**: 对同一批开放题答卷样本，语义主题聚类相较现有关键词共现分组，在"同义不同字"回答的归类准确性上的人工认可率不低于 85%。
- **SC-003**: 设计助手在其知识库覆盖范围内的问题上，至少 90% 的回答能够提供可核实的引用来源；对知识库未覆盖的问题，100% 明确告知"未找到相关依据"而非伪造引用。
- **SC-004**: 建立至少 20 条典型查询的评测集合，检索结果命中用户预期相关模板/文档的比例（Top-5 命中率）不低于 80%。
- **SC-005**: 95% 的检索类请求（相似模板查询、设计助手问答检索环节）能在 1 秒内返回结果，不影响用户操作的流畅度。
- **SC-006**: 检索或索引环节发生故障/超时时，问卷生成、答卷分析、设计助手问答三大场景的核心流程可用率保持 100%（即不因该环节异常导致核心流程失败）。

## Assumptions

- 问卷模板库、知识文档、答卷开放题文本均复用现有系统已有的存储与鉴权体系，本功能不引入新的独立用户身份或权限体系。
- 知识库的初始内容以管理员预先整理、导入项目已有的问卷设计相关资料为主，不面向普通用户开放自由上传知识文档的入口。
- "语义主题聚类"场景中，可支撑聚类的最小有效答卷样本量默认参考现状文档中的经验值（约 10 条），后续可根据实际效果调整。
- 混合检索的语义/关键词权重默认采用现状文档给出的经验值（语义权重高于关键词权重），并保留可调整的空间。
- 本功能不改变现有"问卷生成""答卷分析""设计助手问答"三大场景的现有交互入口，而是在其已有流程内部增强检索与依据能力。
- 涉及答卷开放题文本的向量化索引，遵循与现有答卷数据一致的访问权限范围（即问卷所有者/授权分析人员可见范围），不扩大数据可见范围。
- 移动端/小程序等非本次功能重点适配范围，本功能优先保障现有 Web 端管理后台与生成/分析入口的体验。
- ai-service 侧不新增独立的向量存储或对 q-server 数据存储的直连通道，所有持久化的问卷模板/知识文档 Embedding 的计算、存储与检索均由 q-server 侧统一完成与管理，ai-service 通过既有内部 API 获取检索结果，不参与该类持久化数据的 Embedding 计算；语义聚类等一次性 Embedding 计算无需持久化，可由 ai-service 自行完成。
