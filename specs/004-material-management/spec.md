# Feature Specification: 物料（图片资源）管理模块

**Feature Branch**: `004-material-management`

**Created**: 2026-07-19

**Status**: Draft

**Input**: User description: "为问卷系统开发一个完整的物料管理功能模块，用于对问卷及用户相关的所有图片资源进行全面的CRUD（创建、读取、更新、删除）操作，当前阶段MinIO存储服务仅处理图片资源类型。该功能模块需满足以下具体要求：1. 权限控制：仅系统管理员账户可访问并管理全部物料资源，实现严格的权限校验机制；2. 功能实现范围：后端在q-server开发物料管理API，前端新增独立的物料管理路由页面；3. 接口设计要求：实现完整的图片资源CRUD操作接口，预留物料审核相关接口（状态标记、审核结果处理、审核流程控制），为后续接入审核agent做准备；4. 代码实现要求：遵循现有项目代码规范，实现数据模型和数据库表结构变更，添加错误处理和日志记录，编写单元测试；5. 后续扩展性考虑：设计时考虑未来支持非图片类型资源，审核流程接口可灵活对接不同审核agent系统。"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 管理员浏览全平台物料资产 (Priority: P1)

系统管理员登录后台后，需要能在一个统一的界面里看到平台上所有与问卷、用户相关的图片资源（不论它们来自哪份问卷、哪个用户上传），并能按所属用户、所属问卷、审核状态等条件筛选/搜索，从而掌握平台上究竟存在哪些图片资产。

**Why this priority**: 没有"看得到全部物料"这个能力，后续的删除、更新、审核都无从谈起；这是本功能的地基，独立交付即可让管理员第一次拥有全局可见性，具备独立业务价值。

**Independent Test**: 以管理员账号登录，进入物料管理页面，能看到系统中已存在的图片资源列表（覆盖问卷题目图片、签名图片、用户头像等既有图片来源），并能按用户/问卷/状态筛选出结果。

**Acceptance Scenarios**:

1. **Given** 系统管理员已登录，**When** 进入物料管理页面，**Then** 页面展示平台当前全部图片物料的列表（含缩略图、所属对象、上传时间、审核状态等基本信息）。
2. **Given** 管理员在物料列表页，**When** 按"所属用户"或"所属问卷"或"审核状态"进行筛选，**Then** 列表仅显示满足筛选条件的物料。
3. **Given** 一名非管理员的普通登录用户，**When** 尝试访问物料管理页面或调用其接口，**Then** 请求被拒绝，且不返回任何物料数据。

---

### User Story 2 - 管理员删除物料 (Priority: P2)

管理员在浏览物料列表时，发现违规、废弃或不再需要的图片资源，需要能够将其删除，同时确保底层存储的文件也被一并清理，不留孤儿文件。

**Why this priority**: 在具备"可见"能力之后，"删除"是治理平台内容最直接、诉求最强的动作（清理违规/过期内容），价值仅次于可见性本身，且实现相对独立。

**Independent Test**: 管理员在物料列表中选中一条记录执行删除，之后再次刷新列表，该记录不再出现，且原图片链接不可访问。

**Acceptance Scenarios**:

1. **Given** 管理员在物料列表页选中一条物料，**When** 执行删除操作，**Then** 该物料的记录与其对应的底层文件均被移除，列表中不再展示。
2. **Given** 一条物料仍被某个已发布问卷的题目、用户资料等处主动引用，**When** 管理员尝试删除该物料，**Then** 系统阻止本次删除，并明确告知管理员该物料当前仍被哪些对象引用，要求先解除引用关系后才能删除。
3. **Given** 管理员批量选中多条物料执行删除，**When** 其中部分删除失败（如文件已不存在于存储中），**Then** 系统需明确报告哪些成功、哪些失败，不能静默丢弃失败项。

---

### User Story 3 - 管理员更新物料信息与审核状态 (Priority: P3)

管理员需要能够修正物料的元信息（例如所属分类、关联关系等），也需要能够手动查看和变更物料的审核状态（待审核/已通过/已驳回），作为在自动化审核能力上线之前的人工兜底手段，也是未来审核 Agent 接入的落点。

**Why this priority**: 依赖 User Story 1 提供的可见性，属于对既有物料的精修能力；审核状态的读写是本功能里为"后续接入审核 Agent"预留的关键接口，优先级高于新增上传（Story 4），但低于浏览与删除这两个更基础的治理能力。

**Independent Test**: 管理员对一条物料手动将审核状态从"待审核"改为"已通过"（或"已驳回"），刷新后状态变更生效，且系统记录了这次变更的操作人与时间，可供事后审计。

**Acceptance Scenarios**:

1. **Given** 一条物料当前审核状态为"待审核"，**When** 管理员将其标记为"已通过"或"已驳回"，**Then** 物料状态随之更新，并记录本次变更的操作人、时间。
2. **Given** 管理员修改一条物料的元信息（如分类标签），**When** 保存修改，**Then** 更新内容在物料详情中即时可见。
3. **Given** 审核状态变更能力已开放，**When** 未来一个自动化审核流程（而非人工管理员）调用同一变更能力，**Then** 系统同样接受并记录该次变更，不要求变更者必须是人工管理员账号。
4. **Given** 一条物料的审核状态为"已驳回"，**When** 该物料仍被某处问卷/资料引用，**Then** 该状态仅作为管理侧的标记与留痕，不影响物料在原有引用位置的实际展示——当前阶段审核状态不产生任何业务侧的展示或可用性约束。

---

### User Story 4 - 管理员直接上传新物料 (Priority: P4)

管理员需要能够在物料管理页面直接上传新的图片资源（而不必经过问卷编辑器的既有上传入口），用于补充平台级素材（例如通用素材库、模板封面图预置素材等场景）。

**Why this priority**: 现有问卷编辑器已经具备图片上传能力，本 Story 只是为管理侧新增一个补充入口，紧迫性低于浏览、删除、审核这三项治理能力，属于锦上添花但仍在既定范围内。

**Independent Test**: 管理员在物料管理页面选择一张图片文件直接上传，上传成功后该物料出现在物料列表中，且可被正常筛选与查看。

**Acceptance Scenarios**:

1. **Given** 管理员在物料管理页面，**When** 选择一个图片文件并提交上传，**Then** 系统保存该文件并在物料列表中新增一条对应记录。
2. **Given** 管理员尝试上传一个非图片类型的文件，**When** 提交上传，**Then** 系统拒绝该文件并给出明确的错误提示（当前阶段仅支持图片类型）。

---

### Edge Cases

- 管理员删除仍被已发布问卷、用户资料等主动引用的物料：系统必须阻止删除，并告知具体的引用来源，要求先解除引用。
- 审核状态被标记为"已驳回"后，物料在原引用位置的展示不受影响，仍按原样正常展示——审核状态当前阶段只是管理侧的标记与留痕。
- 同一底层文件被多处引用（例如同一张图被复制用在多个问卷题目）时，删除操作的影响范围如何界定。
- 批量删除/批量状态变更时部分项失败，系统必须明确报告成功与失败的项，不能整体报错也不能静默忽略失败项。
- 非管理员账号（包括未登录访问者）对物料管理任何接口发起的请求，必须被一致拒绝，且拒绝行为本身不应泄露物料是否存在等信息。
- 上传超出平台既有单文件大小/格式限制的图片时，系统必须给出与现有图片上传流程一致的错误提示，而不是引入新的、不一致的限制规则。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须将物料管理功能（查看、创建、更新、删除、审核状态变更）的访问权限严格限制在系统管理员角色范围内；任何非管理员账号或未登录请求发起的相关操作必须被拒绝。
- **FR-002**: 系统必须为管理员提供一个跨越全平台的物料清单视图，涵盖当前系统中已存在的、与问卷或用户相关的全部图片资源，不区分它们最初来自哪个功能入口。
- **FR-003**: 管理员必须能够按至少以下维度筛选/搜索物料清单：所属用户、所属问卷、当前审核状态。
- **FR-004**: 系统必须允许管理员永久删除指定物料（在该物料不存在有效引用、满足 FR-014 前提的情况下），删除操作须同时清除该物料对应的底层存储文件与其管理记录，不遗留孤儿文件。
- **FR-005**: 系统必须允许管理员批量删除多条物料，并在操作完成后明确报告每一项的成功或失败结果；因存在引用而被阻止删除（FR-014）须作为一种明确的失败原因单独呈现，与其他失败原因（如存储异常）区分开。
- **FR-006**: 系统必须允许管理员更新物料的元信息（例如分类归属等描述性信息），但不通过"更新"操作替换物料底层的文件内容本身（更换文件视为删除旧物料并新增新物料）。
- **FR-007**: 系统必须允许管理员通过物料管理界面直接上传新的图片物料，独立于问卷编辑器现有的上传入口。
- **FR-008**: 每条物料记录必须携带一个审核状态字段，其取值集合至少包含"待审核""已通过""已驳回"三种状态，管理员必须能够查看及手动变更该状态。
- **FR-009**: 系统必须记录每一次审核状态变更的操作者、变更后的状态与变更时间，以支撑后续的审计与追溯。
- **FR-010**: 审核状态变更能力必须以"变更者可以是人工管理员，也可以是未来的自动化审核流程"为前提设计，即该能力不能假定发起变更的一方必然是通过管理员界面手动操作的人。
- **FR-011**: 系统在当前阶段必须仅接受图片类型文件作为物料上传内容，对非图片类型文件的上传请求必须拒绝并给出明确提示。
- **FR-012**: 物料记录对其"底层资源类型"（当前仅"图片"一种）的表达方式必须具备可扩展性，使未来引入非图片类型资源时不需要推翻现有物料记录的设计。
- **FR-013**: 系统必须对物料管理相关的每一次创建、更新、删除、审核状态变更操作留存操作日志，记录操作人、操作类型、操作对象与时间，供事后追查。
- **FR-014**: 删除一条仍被其他业务对象（如已发布问卷题目、用户资料）主动引用的物料时，系统必须阻止该次删除，并向管理员明确告知当前存在哪些引用，引导其先解除引用后再删除；系统不得在存在有效引用的情况下静默完成删除。
- **FR-015**: 审核状态变更（尤其是"已驳回"）在当前阶段必须仅作为管理侧的标记与审计留痕，不得对物料在其原有引用位置的实际展示或可用性产生任何影响；审核状态与业务侧展示逻辑保持解耦。

### Key Entities _(include if feature involves data)_

- **物料（Material）**：被管理的单个图片资源本身。关键信息包括：唯一标识、底层资源类型（当前恒为"图片"，为未来扩展预留）、原始文件名与大小、所属关联（属于哪个用户/哪份问卷/哪个使用场景，可能为空表示未关联到具体业务对象）、当前审核状态、上传者、创建与更新时间。
- **审核状态变更记录（Review Decision）**：针对某条物料发生的一次审核状态变化。关键信息包括：所属物料、变更前后的状态、变更者（可能是人工管理员，也可能是未来的自动化审核流程）、变更时间、可选的审核意见/原因说明。用于支撑审计追溯，也是未来审核 Agent 读写状态的落点。
- **系统管理员（Administrator）**：唯一被允许执行本功能全部操作的用户角色，区别于平台上的普通登录用户。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 管理员可以在 1 分钟内，通过筛选（按用户/问卷/审核状态）从平台全部物料中定位到目标物料，无需借助开发人员或数据库工具。
- **SC-002**: 非管理员身份（包括未登录）对物料管理功能发起的访问尝试，100% 被拒绝，且不泄露任何物料数据。
- **SC-003**: 管理员对新上传或存量物料完成一次审核状态标记（待审核→已通过/已驳回）全程自助完成，无需开发人员介入。
- **SC-004**: 物料删除操作完成后，对应的底层存储文件与管理记录同步清除；在物料未被其他业务对象引用的常规场景下，孤儿文件残留比例为 0。
- **SC-005**: 未来接入自动化审核流程时，此前人工产生的审核状态与变更记录无需迁移或重新解释即可被自动化流程直接读取和延续使用。

## Assumptions

- "问卷及用户相关的所有图片资源"覆盖系统内已经存在的各类图片来源（例如问卷题目图片、签名图片、用户头像等），本功能是在这些既有资源之上新增的管理层，而不是要求先重新采集或迁移一套全新的图片资源。
- 普通用户上传图片的既有入口（如问卷编辑器）保持不变，本功能只新增管理员侧的统一管理能力，不改变普通用户的上传体验。
- "当前阶段 MinIO 仅处理图片资源类型"是平台既有的整体约束，并非本功能独有限制；非图片类型资源的支持明确排除在本次范围之外，但设计上不能妨碍未来添加。
- 目前不存在真正的自动化审核 Agent；"预留审核接口"意味着审核状态的读写与审计能力必须建成并可用，但审核 Agent 本身的实现不在本功能范围内。
- 物料管理相关的操作日志记录方式沿用平台现有的审计日志机制与规范，不需要另建一套独立的日志体系。
- 批量删除、批量状态变更等批量操作的具体数量上限等细节，沿用平台现有同类批量接口的既有惯例，除非后续规划阶段发现需要专门约束。
