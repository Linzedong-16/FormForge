# Quickstart: 验证物料（图片资源）管理模块

本指南用于端到端验证本功能在本地开发环境下按预期工作，不包含实现代码，仅描述前置条件、启动步骤与验证场景。接口契约细节见 [contracts/media-assets-api.md](./contracts/media-assets-api.md)，数据结构见 [data-model.md](./data-model.md)。

## 前置条件

1. 已完成本地基础设施依赖（PostgreSQL、Redis、MinIO；RabbitMQ/ClickHouse/MongoDB 与本功能无关，可不启动）。
2. 已执行 Prisma 迁移，`media_assets` 表（由 `survey_files` 演进而来）已就位，且已跑过一次性迁移逻辑，为 `avatar.service.ts` 新增的头像登记逻辑生效。
3. 拥有一个 `super_admin` 角色账号（q-server 首个注册用户自动获得该角色，见 `auth.service.ts` 既有逻辑），以及一个普通用户账号（用于验证权限拒绝场景）。
4. 系统中已存在至少：一份已发布问卷且题目中包含一张图片选择题封面图、一个已设置头像的用户资料——用于验证"跨来源统一可见"（User Story 1）与"引用检测阻止删除"（User Story 2 场景 2）。

## 启动

```bash
# 后端
cd app/q-server && pnpm dev

# 前端管理后台
cd app/frontend && pnpm dev
```

## 验证场景

### 场景 1：管理员可见性（User Story 1，P1）

1. 使用 `super_admin` 账号登录 `app/frontend`。
2. 导航至"系统管理 → 物料管理"（`/media-assets`）。
3. **预期**：列表中同时出现该已发布问卷的题目图片与该用户的头像，二者来源不同但在同一列表中呈现；按"所属问卷"筛选后，仅剩问卷图片；按"所属用户"筛选，仅剩该用户上传的资源（含其头像）。
4. 退出登录，改用普通用户账号访问同一路由（或直接调用 `GET /api/admin/media-assets`）。
5. **预期**：前端路由被 `requiresSuperAdmin` 守卫拦截跳转首页；直接调接口返回 `403`，`data: null`。

### 场景 2：删除保护（User Story 2，P2）

1. 以管理员身份，在列表中找到步骤 1 里那张仍被已发布问卷引用的题目图片，尝试删除。
2. **预期**：删除被拒绝（`409`），界面提示具体的引用来源（问卷标题）。
3. 找到一张确认未被任何问卷/用户资料引用的物料（如直接通过场景 4 上传的测试图片），执行删除。
4. **预期**：删除成功，列表刷新后该条记录消失，原 `fileUrl` 不可再访问。
5. 勾选多条物料（混合"可删除"与"仍被引用"两类）执行批量删除。
6. **预期**：响应中 `succeeded`/`failed` 两个列表分别列出对应 ID，界面需要将两类结果分别呈现，不能笼统报"操作失败"。

### 场景 3：元信息与审核状态（User Story 3，P3）

1. 选中任意一条物料，将其 `reviewStatus` 由 `pending` 改为 `approved`，填写审核意见。
2. **预期**：状态更新即时生效；再次查看详情，`reviewedBy`/`reviewedAt`/`reviewComment` 均已填充为本次操作信息。
3. 回到场景 1 中仍被已发布问卷引用的那张图片，将其状态改为 `rejected`。
4. **预期**：状态变更成功；重新打开该问卷的填答/预览页面，图片仍正常显示——审核状态变更**不影响**其原有引用位置的展示（对应 spec.md Q2 澄清结论）。
5. （可选，验证 FR-010）使用一个持有等效管理员授权的脚本/客户端（而非前端界面）直接调用 `PUT /api/admin/media-assets/:id/review-status`。
6. **预期**：调用同样成功，证明该接口不假设调用方必须来自人工操作的前端界面。

### 场景 4：直接上传（User Story 4，P4）

1. 在物料管理页面使用"上传物料"入口，选择一张图片文件提交。
2. **预期**：上传成功，新记录出现在列表中，`reviewStatus` 默认为 `pending`。
3. 改为提交一个非图片文件（如 `.pdf`）。
4. **预期**：上传被拒绝（`415`），提示"当前阶段仅支持图片类型文件"。
