# Feature Specification: 问卷答卷基础统计与 CSV 导出

**Feature Branch**: `001-survey-basic-stats`

**Created**: 2026-07-24

**Status**: Draft

**Input**: User description: "按题型分策略的答卷聚合分析与 CSV 导出——仅做基础统计范畴，不考虑有对错的答卷式业务"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 查看单问卷逐题统计 (Priority: P1)

管理员进入某份已发布问卷的统计详情页，看到每道题的统计数据。系统按题型自动采用合适的统计维度：选择题展示各选项的频次和百分比，评分题展示平均值和分布，文本题展示抽样原文。管理员可以直观了解受访者对每一题的回答分布。

**Why this priority**: 这是答卷分析的核心场景。管理员查看问卷结果时，最需要的就是逐题分布数据，缺少这个功能统计模块就没有价值。

**Independent Test**: 选择任意一份有答卷数据的问卷，进入统计详情页，验证每一道题都展示了对应题型维度的统计数据。即使平台汇总仪表盘尚未开发，也能独立交付价值。

**Acceptance Scenarios**:

1. **Given** 一份已发布的单选题问卷（如"满意度调查"），已有 50 份答卷，**When** 管理员进入该问卷的统计详情页，**Then** 看到该单选题各选项的频次（如"非常满意 30 人"）和百分比（"60%"），以及总答题人数。
2. **Given** 一份含有多选题的问卷，已有答卷数据，**When** 管理员查看该多选题统计，**Then** 看到每个选项被选中的次数和占总选择次数的百分比。
3. **Given** 一份含有评分题的问卷，已有答卷数据，**When** 管理员查看评分题统计，**Then** 看到平均值、最小值、最大值，以及各分值的频次分布。
4. **Given** 一份含有文本题的问卷，已有答卷数据（超过 10 份），**When** 管理员查看文本题统计，**Then** 看到最近 10 条原文抽样及总答案数。
5. **Given** 一份尚未收到任何答卷的问卷，**When** 管理员进入统计详情页，**Then** 看到每道题标注"暂无数据"，总答卷数为 0。

---

### User Story 2 - 查看平台汇总仪表盘 (Priority: P2)

管理员登录后台后，在仪表盘看到平台的答卷数据概览：累计答卷总数、已发布问卷数、今日新增答卷、本周新增答卷，以及近 7 天的每日答卷趋势。这个入口视图帮助管理员快速了解平台的运营状况。

**Why this priority**: 平台汇总页面是登录后的第一入口，提供全局视角。但它依赖的是已有统计 API，不阻塞 P1（单问卷详情）的开发。

**Independent Test**: 登录后台进入仪表盘，验证统计卡片数值与实际数据一致，7 日趋势图正确显示每日答卷数量。

**Acceptance Scenarios**:

1. **Given** 平台已有若干问卷和答卷记录，**When** 管理员登录进入仪表盘，**Then** 看到"累计答卷总数""已发布问卷""今日新增""本周新增"四个指标卡片，数值与实际数据一致。
2. **Given** 近 7 天有部分日期无答卷，部分日期有答卷，**When** 管理员查看 7 日趋势图，**Then** 无答卷的日期显示为 0，有答卷的日期显示实际数值，日期按时间顺序排列。

---

### User Story 3 - 导出答卷数据为 CSV (Priority: P3)

管理员在查看某份问卷的统计详情时，点击"导出 CSV"按钮，下载一份包含该问卷全部原始答卷的 CSV 文件。文件用 Excel 打开时中文正常显示，每行代表一份答卷，每列代表一道题，多选答案用分号分隔。

**Why this priority**: CSV 导出是数据分析的"最后一步"——管理员可能需要把原始数据拿到外部工具做进一步处理。它是独立功能，不阻塞 P1 和 P2。

**Independent Test**: 对任意有答卷的问卷触发导出，验证浏览器下载了一个 CSV 文件，文件内容（表头、数据行、中文编码、多选分隔符）符合预期。

**Acceptance Scenarios**:

1. **Given** 一份有 10 份答卷、3 道题的问卷，**When** 管理员点击"导出 CSV"，**Then** 浏览器下载一个 CSV 文件，第 1 行为表头（答卷编号、提交时间、匿名 ID、各题标题+题型标注），后续 10 行为答卷数据。
2. **Given** CSV 文件中包含中文内容，**When** 管理员用 Excel 打开该文件，**Then** 中文字符正常显示（不乱码）。
3. **Given** 一份答卷包含多选题答案 ["选项A", "选项B"]，**When** 导出为 CSV，**Then** 对应单元格的值为 "选项A;选项B"（分号分隔）。
4. **Given** 某份问卷没有任何答卷，**When** 管理员点击导出，**Then** 导出的 CSV 内容为"暂无答卷数据"。

---

### Edge Cases

- 文本题答案包含逗号、引号或换行符时，CSV 导出应正确转义（双引号包裹 + 内部引号加倍），Excel 能正确解析。
- 问卷包含已被删除的组件（组件 ID 在答案中存在但问卷当前版本中已移除），统计概览和导出时这些答案应被静默跳过。
- 签名题的答案可能是空字符串（用户清除了签名），应归类为"无签名"而非有效签名。
- 评分题答案值可能包含非数字字符串（脏数据），聚合计算时应过滤掉（`~ '^[0-9]+(\\.[0-9]+)?$'` 正则预检）。
- 矩阵单选题的答案 JSON 解析失败时，应跳过该条记录而非导致整个统计崩溃。
- 答卷量很大时（>10000 份），统计查询应有缓存保护，避免每次页面刷新都执行全表聚合。
- 同时有多个管理员导出同一问卷的 CSV 时，每个请求独立响应，不互相干扰。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统必须对选择题（单选、下拉、图片单选）提供各选项的频次统计和百分比，以及总答题人数。
- **FR-002**: 系统必须对多选题（多选、图片多选、排序）提供每个选项被选中的次数和占总选择次数的百分比，多选答案通过 JSON 数组展开方式逐元素聚合。
- **FR-003**: 系统必须对评分题和滑块题提供平均值、最小值、最大值，以及各分值的频次分布。
- **FR-004**: 系统必须对矩阵单选题提供每行×每列的交叉频次统计，每行独立统计各列选择占比。
- **FR-005**: 系统必须对日期时间题和级联选择题提供按值分组的频次分布。
- **FR-006**: 系统必须对文本题和个人信息题（约 15 种）提供最近 10 条答案原文抽样，以及总答案数和空值率。
- **FR-007**: 系统必须对电子签名题仅统计有签名和无签名的数量，不做图像内容分析。
- **FR-008**: 系统必须提供平台级统计概览：问卷总数、已发布问卷数、累计答卷总数、今日新增答卷、本周新增答卷、近 7 天每日答卷趋势。
- **FR-009**: 系统必须支持将单份问卷的原始答卷数据导出为 CSV 文件，每行一份答卷，每列一道题，多选答案用分号分隔。
- **FR-010**: 导出的 CSV 文件必须包含 UTF-8 BOM 头，确保 Excel 打开时中文正确显示。
- **FR-011**: CSV 文件名格式必须为 `survey_{问卷ID}_{问卷标题}.csv`。
- **FR-012**: 展示型组件（如"备注说明"）必须从统计范围内排除，不产生统计条目。
- **FR-013**: 统计结果必须缓存（缓存时长 5 分钟），新答卷提交时相关缓存必须失效，确保数据新鲜度。
- **FR-014**: 单问卷统计详情页必须能独立访问（通过 URL 路由，如 `/survey-management/statistics/{id}`），支持从问卷列表跳转进入。

### Key Entities

- **答卷 (Response)**: 代表一份完整的问卷提交记录，包含提交时间、匿名标识、状态（已提交/未完成）和一组答案。
- **答案 (Answer)**: 答卷中某一道题的回答，包含关联的题目组件 ID、单值文本（value）或多值数组（values）。
- **问卷组件 (SurveyComponent)**: 问卷中的一道题，包含类型（题型标识）、排序序号、配置（含题目标题和选项标签）。
- **题目统计 (QuestionStats)**: 一道题的聚合分析结果，包含题型、标题、总答案数、以及按题型维度不同的统计数据（选项分布/平均值/抽样答案等）。
- **统计概览 (StatsOverview)**: 平台级汇总数据，包含各维度的答卷数量指标和日趋势数据。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 管理员能在 3 秒内从问卷列表进入某份问卷的统计详情页并看到完整的逐题统计数据。
- **SC-002**: 单问卷统计查询（含逐题聚合分析）在 1000 份答卷规模下，首次查询在 3 秒内完成；缓存命中时在 1 秒内完成。
- **SC-003**: 导出的 CSV 文件使用 Excel 打开后，100% 的中文字符正确显示，无乱码。
- **SC-004**: 1000 份答卷的 CSV 导出在 10 秒内完成下载。
- **SC-005**: 统计页面对 30 种题型中的每一种都能展示适合该题型的统计维度，不存在题型无统计或统计维度错配。
- **SC-006**: 管理员无需查阅帮助文档即可理解统计图表含义（每个统计项有对应的题型类型标注和选项标签）。

## Assumptions

- 目标用户是已登录的管理员（含超级管理员和问卷所有者），不需要面向匿名用户的统计视图。
- 统计模块复用已有的后端聚合引擎和 API 端点，本需求仅涉及前端展示层的补全。
- 选项标签存储在组件配置 JSON 中，后端聚合时已能正确还原为人类可读标签。
- CSV 导出仅包含原始答卷数据，不包含聚合分析结果（聚合数据在前端页面查看即可）。
- 文本题和个人信息题均视为定性数据，仅做抽样展示，不做关键词提取或词频分析。
- 前端管理后台使用已有的 Arco Design Vue 组件库，不引入新的 UI 框架。
- 统计页面的鉴权复用现有的管理员中间件（`authenticate` + `requireSuperAdmin`），不新增权限体系。
